=====================================================
 HTML
=====================================================

[요소 종류]
block (div, p, h1, ul...) → 한 줄 독차지 → 세로로 쌓임
inline 계열 (input, button...) → 자기 폭만 차지 → 가로로 나란히

[class / id]
class 는 띄어쓰기 금지, 하이픈으로 연결 (예: date-card)
class 는 중복 가능 (여러 요소가 같은 class 공유)
id 는 고유 (문서에서 딱 하나)
→ 스타일 줄 땐 주로 class, 하나뿐인 건 id

[공백 처리]
HTML 은 공백을 접는다 (whitespace collapsing)
화면엔 앞뒤/연속 공백 안 보여도 데이터엔 살아있음
→ 그래서 .trim() 으로 직접 정제해야 함
"화면이 깨끗해 보여도 데이터는 더러울 수 있다"

[구조 vs 스타일]
HTML 구조 변경은 마지막 수단
CSS로 해결되는 걸 div 추가로 풀면 의미 없는 태그가 쌓임 ("div 수프")
→ 구조는 의미, 배치는 CSS. 역할 분리

[하드코딩 vs JS 생성] 판단 기준
"이 데이터가 변할 일이 있나?"
요일 7개 → 절대 안 변함 → HTML 하드코딩
날짜 칸 → 달마다 28~31개 → JS 생성
※ "반복되니까 무조건 JS" 는 함정


=====================================================
 CSS
=====================================================

[연결]
<link rel="stylesheet" href="style.css"> 를 head 안에

[문법]
선택자 { 속성: 값; }
class 선택은 앞에 점(.)  →  .date-card
줄 끝마다 세미콜론(;) 필수

[자주 쓰는 속성]
background-color : 배경색
color            : 글자색
padding          : 상자 안쪽 여백
margin           : 상자 바깥쪽 여백
border-radius    : 모서리 둥글기 (숫자 클수록 둥글)
font-size        : 글자 크기

[색상]
HEX 코드: #RRGGBB (빨강/초록/파랑 각 00~ff)
글자색은 순검정(#000)보다 살짝 회색(#333)이 눈에 편함

[상속]
글자 스타일(color, font-size)은 자식에게 흘러내림 (상속 O)
상자 스타일(background, padding, margin)은 상속 X
(파이썬 클래스 상속과 비슷 - 자식이 따로 정하면 그게 우선)

[Flexbox]
부모에 display: flex  →  자식들 가로로 배치
정렬은 자식이 아니라 "부모"가 지휘한다
justify-content : center / flex-start / flex-end / space-between / space-around
gap : 자식들 사이 간격

[Grid]
display: grid
grid-template-columns: repeat(7, 1fr)  → 7칸 균등 분할
1fr = 남은 공간의 비율 단위
※ 두 요소를 세로로 정렬하려면 columns/gap/폭이 모두 같아야 함

[블록 요소의 폭] ★
블록 요소는 폭을 안 주면 부모를 꽉 채운다
→ 크기를 자식마다 정하지 말고 부모 하나만 잡기
   (부모 바뀌면 자식 전부 고쳐야 하는 상황 방지)
"이 요소 폭 얼마로 하지?" 보다
"부모가 이미 정해주지 않았나?" 를 먼저 묻기

[중앙 정렬]
margin: 0 auto  → 위아래 0, 좌우 자동 = 가운데
※ max-width 가 있어야 작동 (폭이 꽉 차면 밀 공간이 없음)
※ 부모가 가운데 가면 자식은 따라옴 (자식마다 정렬 X)

[가상 클래스 pseudo-class]
:hover  → 마우스 올렸을 때
:active → 누르는 중
:focus  → 입력창 선택됨
= "상태에 따른 조건부 스타일"

[가상 요소 pseudo-element]
::after → 요소 뒤에 가짜 내용 삽입 (content 속성 필요)
※ 콜론 2개 = 요소, 1개 = 클래스

[우선순위 specificity] ★
id(#) > class(.) > 태그
→ 순서와 무관하게 id 가 이김
→ 같은 등급끼리는 나중에 쓴 게 이김 (cascade)
※ 실무: id 는 스타일링에 잘 안 씀 (너무 세서 나중에 못 덮음)
  #add-btn 보다 .btn-primary 같은 class 권장

[패딩 축약]
padding: 8px         → 사방 8
padding: 8px 16px    → 위아래 8, 좌우 16

[CSS 파일 정리]
1. 화면에 보이는 순서대로 (HTML 순서와 맞추기)
2. 관련 규칙은 붙여 쓰기 (.day 바로 밑에 .day:hover, .selected)
3. 덜 구체적 → 더 구체적 (덮어쓰는 쪽이 아래로)
※ 300줄 넘으면 파일 분리 or CSS 변수(--main-color) 고려

[스타일이 거짓말하지 않게]
cursor: pointer 는 실제로 클릭되는 요소에만
클릭 안 되는데 손가락 커서 = 사용자 속이는 것

=====================================================
 JavaScript
=====================================================

[연결]
<script src="script.js"></script> 는 body 의 제일 아래
이유: JS가 조작할 요소(버튼 등)가 먼저 존재해야 하기 때문

[변수]
const : 값을 다시 안 바꿀 변수 (상수)
let   : 값이 바뀌는 변수

const/let = "변수를 만드는" 키워드 (담는 통을 준비)
new = "객체를 만드는" 키워드 (통에 담을 물건을 생성)

[DOM]
DOM (Document Object Model) = JS가 바라보는 웹페이지
= JS가 조작할 수 있는 "살아있는 화면"
※ DOM 을 바꿔도 index.html 파일 자체는 안 바뀜
  (새로고침하면 파일을 다시 읽어서 DOM 변경분은 사라짐)

[글자 읽고 쓰기]
일반 요소(p, h2, 버튼)의 글자 → .textContent
입력창(input)의 값          → .value
입력창 비우기 → input.value = ""

[이벤트 3단 패턴] ★핵심★
1. 요소 찾기   : document.getElementById("id")
2. 귀 달기     : 요소.addEventListener("click", 함수)
3. 반응        : function() { ... 실행할 일 ... }
→ 모든 상호작용의 뼈대. 클릭/저장/삭제 다 이 패턴

[요소 선택]
getElementById("id")     : id로 찾기
querySelector("li")      : 조건에 맞는 "첫 번째" 하나만
querySelectorAll("li")   : 조건에 맞는 "전부"
※ CSS 선택자 문법 그대로 사용 (.class, li 등)

[DOM 조작]
document.createElement("li")  : 새 요소 만들기 (아직 화면엔 없음)
부모.appendChild(자식)         : 자식으로 붙이기 (화면에 나타남)
요소.remove()                 : 요소 통째로 제거

[비교 연산자]
=== (엄격) : 값도 타입도 같아야 참  → 항상 이걸 씀
==  (느슨) : 타입을 멋대로 바꿔서 비교 → 예측 불가, 쓰지 말 것
예: 5 === "5" → false / 5 == "5" → true (함정)

[배열 = 파이썬 리스트]
.push(값)         : 맨 끝에 추가      (파이썬 append)
.length           : 개수             (파이썬 len)
.forEach(함수)     : 하나씩 반복        (파이썬 for x in list)
.indexOf(값)      : 값의 위치 찾기     (파이썬 index) / 없으면 -1
.splice(위치, 개수) : 특정 위치의 것 제거

[함정] indexOf 는 "첫 번째" 값만 찾음
→ 같은 값이 여러 개면 구분 못 함
→ 해결: 각 데이터에 고유 id 를 붙여서 id로 찾기

[JSON] (localStorage는 문자열만 저장 가능해서 필요)
JSON.stringify(배열)  : 배열 → 문자열 (저장할 때)  = 파이썬 json.dumps
JSON.parse(문자열)    : 문자열 → 배열 (꺼낼 때)   = 파이썬 json.loads

.toString() 은 "대충 문자열로" → 되돌리기 불가, 정보 손실
JSON.stringify 는 "규칙대로 정확히" → 되돌리기 가능, 정보 보존
※ JSON = 데이터를 문자열로 표현하는 전 세계 공통 약속

[localStorage] 브라우저 저장 공간 (새로고침/재부팅해도 유지)
localStorage.setItem("키", "값")  : 저장
localStorage.getItem("키")        : 꺼내기
※ 문자열만 저장 가능
※ 첫 방문자는 저장된 게 없어서 null 반환 → null 체크 필요

[세미콜론]
function 이름() { }        → 세미콜론 X (선언)
const x = function() { };  → 세미콜론 O (할당)
요소.addEventListener();   → 세미콜론 O (호출)
원칙: {} 로 끝나는 선언은 X, 나머지 문장은 O

[호이스팅]
function 선언은 미리 등록돼서 위치가 자유로움 (아래 있어도 위에서 호출 가능)
단, 실행문(loadRecords();)은 재료(요소/변수)가 준비된 맨 아래에 둠

[배열 메소드 추가]
.filter(함수)  : 조건 맞는 것만 골라 새 배열 (파이썬 리스트 컴프리헨션)
.some(함수)    : 하나라도 조건 맞으면 true (파이썬 any)
→ 둘 다 원본을 안 바꿈. 새 결과를 반환

[Date 객체]
new Date()                    : 현재 시각
new Date(년, 월, 일)           : 특정 날짜
.getFullYear() / .getMonth() / .getDate() / .getDay()
※ getMonth() 는 0부터! (0=1월, 11=12월)
※ getDate()=며칠 / getDay()=무슨 요일(0=일요일)

[Date 트릭]
new Date(y, m+1, 0).getDate()  → 그 달의 마지막 날
  (다음 달 0일 = 이번 달 말일)
new Date(y, m, 1).getDay()     → 그 달 1일의 요일 (앞 빈칸 개수)
※ 범위 초과 시 자동 조정 (month=12 → 다음 해 1월)

[문자열 포맷]
String(숫자)          : 숫자 → 문자열
.padStart(2, "0")     : 앞을 채워 자릿수 맞춤 (7 → "07")
→ "2026-07-08" 형식 만들기. 날짜는 문자열 비교가 편함

[상태 state 변수] ★
selectedDate, currentYear 처럼 "지금 화면이 무엇을 보여주는지" 담는 변수
데이터(records)와 별개로 관리

[단방향 데이터 흐름] ★★
상태가 바뀌면 → 화면 전체를 다시 그린다 (render)
필요한 부분만 콕 집어 고치지 않는다 (patch)

나쁜 예: 클릭한 칸에 직접 classList.add("selected")
        → 이전 선택 지우는 코드를 따로 관리해야 함
좋은 예: selectedDate 값만 바꾸고 renderCalendar() 다시 호출
        → 지웠다 새로 그리니 이전 상태가 남을 수 없음

"화면은 상태의 결과물이다" - React 등 현대 프레임워크의 핵심 사상

=====================================================
 백엔드 기초 개념
=====================================================

[클라이언트 / 서버]
클라이언트 = 요청하는 쪽 (브라우저)
서버       = 응답하는 쪽 (파이썬 프로그램)
★ 요청은 항상 브라우저가 먼저 보낸다. 서버는 절대 먼저 말 안 검
★ 서버 = 컴퓨터가 아니라 "요청을 기다리는 프로그램"

프론트엔드 = 브라우저에서 도는 코드 (html/css/js)
백엔드     = 서버에서 도는 코드 (app.py)

[요청-응답]
오가는 건 프로그램이 아니라 "글자(데이터)" 뿐
요청 예:
    POST /api/records HTTP/1.1
    Content-Type: application/json
    {"id":123,"text":"영화"}      ← body

[IP / DNS]
IP        : 컴퓨터 주소 (숫자)
DNS       : 이름↔IP 전화번호부. naver.com → 223.130.200.107
127.0.0.1 : "나 자신". 별명은 localhost. DNS 안 거침

[포트 port] ★
한 컴퓨터에서 프로그램 여러 개가 도니까 구분 번호가 필요
    IP   = 건물 주소 / 포트 = 호수
프로그램이 켜질 때 "5000번 요청은 내가 받는다"고 점유
    Flask 5000 / Live Server 5500
    http 80 / https 443 (기본값이라 주소에서 생략됨)
※ 같은 포트 두 프로그램이 못 씀 → Address already in use

내 쪽에도 포트가 있음 (54821 같은 임시번호, OS가 배정)
→ 응답이 어느 탭으로 돌아갈지 구분하는 용도
※ 요청 봉투에 "보낸 곳"이 자동으로 붙어서, 서버는 내 주소를 미리 몰라도 됨

[URL 해부]
https:// claude.ai (:443) /chat/abc123
프로토콜   도메인    포트      경로(path)
→ 앞 세 개는 접속하는 데 쓰고 버림
→ Flask가 보는 건 "경로"뿐 (브라우저가 이미 잘라서 보냄)

=====================================================
 Flask
=====================================================

[설치 계층]
① Python 인터프리터(python.exe) : 코드를 실행하는 프로그램
   ※ 언어(문법)와 실행기는 다른 것. IDE는 파이썬을 갖고 있지 않음
     VS Code는 편집기일 뿐, 디스크의 python.exe를 대신 호출할 뿐
② venv  : 프로젝트 전용 격리 환경
③ pip   : 패키지 받아오는 도구
④ Flask : pip으로 받은 파이썬 라이브러리

[가상환경 venv]
파이썬 3.3+ 표준 기능 (따로 설치 X)
    python -m venv venv     ← -m = 모듈 실행. 앞 venv=모듈명, 뒤=폴더명
    venv\Scripts\activate   ← 터미널 설정 변경. (venv) 표시 = 켜짐
    deactivate              ← 끄기
※ 터미널 새로 열면 매번 다시 activate
※ 실체는 그냥 폴더. Scripts\python.exe(복사본) + Lib\site-packages\(패키지 창고)
※ pip install flask = site-packages에 파일 압축 푸는 것. 마법 아님

왜 쓰나: 프로젝트마다 필요한 패키지 버전이 달라서 (A=Flask2.0, B=3.0)
        전역에 하나만 깔면 충돌

[환경 재현]
    pip freeze > requirements.txt   ← 설치 목록 파일로 뽑기 (깃에 올림)
    pip install -r requirements.txt ← 다른 PC에서 복원
※ venv 폴더는 .gitignore (용량 크고 절대경로가 박혀 있어 이식 불가)
   "환경은 옮기는 게 아니라 다시 만드는 것"
.gitignore : venv/ , __pycache__/ , *.pyc

[app.py 뼈대]
    from flask import Flask, render_template, jsonify, request
    app = Flask(__name__)      ← 서버 객체 생성. __name__=파일 위치 알려줌

    @app.route("/")
    def home():
        return "안녕"

    if __name__ == "__main__":     ← 직접 실행할 때만 (import 시 서버 안 켜지게)
        app.run(debug=True)        ← 포트 열고 무한 대기. 터미널 멈춘 게 정상

※ import * 쓰지 말 것 (이름 충돌 / 출처 추적 불가 / 자동완성 안 됨)
※ debug=True : 저장 시 자동 재시작 + 에러 상세 표시
   → 배포 시 반드시 끌 것 (코드 내부가 노출됨)
※ app.run()의 서버는 개발용 장난감. 배포는 gunicorn 등 사용

[라우팅 routing] ★
= "이 주소로 요청 오면 이 함수 실행해라"를 app의 표에 등록
    "/"            → home()
    "/api/records" → records_api()
표에 없으면 404

★ "/" 는 문자 하나가 아니라 주소 전체 (통째로 비교)
   "/about" 은 "/" 와 다른 문자열이므로 중복 아님
★ 127.0.0.1:5000 접속 시 브라우저가 자동으로 "/" 를 붙임 (루트 경로)
★ 함수 이름과 주소는 무관 (관례상 맞춰 지을 뿐)
★ 함수의 return 값 = 브라우저에 보내는 응답
   → 문자열 → HTML → JSON 순으로 발전

동적 라우팅: @app.route("/chat/<chat_id>") → 빈칸에 뭐가 와도 매칭

[정적 파일 규칙]
    프로젝트/
    ├── app.py
    ├── templates/  ← HTML (서버가 가공해서 보냄)
    └── static/     ← css, js, 이미지 (그대로 보냄)
render_template("index.html") → templates/ 안에서만 찾음
static/ 경로는 라우트 없이 Flask가 자동 서빙

HTML에서 경로 쓸 때:
    {{ url_for('static', filename='style.css') }}
※ "/static/style.css" 직접 써도 되지만 X
   → 주소가 바뀔 수 있으므로 "직접 쓰지 말고 계산하게 하라"
※ {{ }} = Jinja2 템플릿 문법. 나중에 파이썬 값을 HTML에 꽂을 때 재사용

[HTTP 메서드] ★
GET    = 달라 (읽기)      ← 본문 없음
POST   = 새로 만들어 (생성) ← body에 데이터 실음
PUT    = 수정
DELETE = 삭제

★ 요청 = 주소 + 메서드 (한 쌍). 하나만으론 성립 안 함
   주소 = 명사(무엇을) / 메서드 = 동사(어떻게)
   POST /api/records vs POST /api/users → 주소가 대상을 지정

    @app.route("/api/records", methods=["GET","POST"])
    def records_api():
        if request.method == "POST":
            data = request.get_json()
            records.append(data)
            return jsonify(data)     ← 저장 결과 확인서
        return jsonify(records)
※ methods 안 적으면 GET만 받음 → POST 오면 405

[REST 설계]
옛날: /getRecords /addRecord /deleteRecord   ← 주소에 동사, 무한 증식
REST: /api/records 하나 + 메서드로 구분

[request 객체]
Flask가 들어온 요청을 파싱해서 담아둠 (내가 만드는 게 아님)
    request.method      → "POST"
    request.path        → "/api/records"
    request.get_json()  → body를 파이썬 dict로  = json.loads 와 같은 일

[API]
Application Programming Interface = 프로그램끼리 대화하는 창구
    /              → 사람이 볼 화면 (HTML)
    /api/records   → 프로그램이 읽을 데이터 (JSON)
/api/ 는 기능이 아니라 관례 (주소만 보고 구분하려고)
JSON 응답의 \uc601 같은 건 깨진 게 아니라 유니코드 escape (정상)

[터미널 로그 읽기] ★내 습관 만들 것★
    127.0.0.1 - - [날짜] "GET /time HTTP/1.1" 200 -
    보낸곳IP            메서드 경로        상태코드
    200=성공 / 404=표에 없음 / 405=메서드 안 맞음
※ favicon.ico 404는 크롬이 자동 요청한 것. 무시
브라우저는 결과만, 터미널은 "왜"를 보여줌
서버 켜진 터미널은 입력 불가 → 터미널 추가로 열기(+)

=====================================================
 프론트-백 연결
=====================================================

[fetch]
= 화면 안 바꾸고 데이터만 받아오는 요청
    주소창 입력 → 응답을 화면에 표시 (페이지 바뀜)
    fetch      → 응답을 JS 변수에 담음 (화면 그대로)
※ 서버 입장에선 둘이 구분 안 됨. 똑같은 요청

    fetch("/api/records")                    ← 옵션 없으면 GET (기본값)
    fetch("/api/records", {
        method: "POST",
        headers: {"Content-Type":"application/json"},  ← 내용물 라벨
        body: JSON.stringify(record)                   ← 보낼 물건
    })

[연결점은 딱 두 군데] ★★
    ① JS의 body       → 파이썬의 request.get_json()   (브라우저→서버)
    ② 파이썬의 return → JS의 response.json()          (서버→브라우저)
그 외엔 서로를 볼 수 없음. 오직 JSON 문자열만 오감

[비동기 async/await] ★
JS는 스레드가 하나 → 기다리면 화면 전체가 얼어붙음
비동기 = 동시 실행(멀티스레드)이 아니라 "대기 시간 활용"
    멀티스레드 = 요리사 2명 (진짜 동시)
    비동기     = 요리사 1명, 물 끓는 동안 야채 썲

await = 그 함수만 일시정지, 스레드는 다른 일 하러 감
async = await를 쓸 수 있게 하는 허가증
★ async는 "await가 적힌 그 함수"에 붙임 (호출하는 쪽 아님)
★ async 함수를 await 없이 호출만 하면 async 불필요

    async function loadRecords(){
        const response = await fetch("/api/records");  ① 응답 대기
        const data = await response.json();            ② 본문 해석 대기
        records = data;
        renderCalendar(...);      ← 데이터 도착 후에 그려야 함
    }

함수 "안"은 순서대로 실행됨. 함수 "밖"이 먼저 실행될 뿐
    실행순서 예: 1 → 3 → 2 → 4 → 5
                (호출 전 → 함수시작 → 호출 후 → 응답도착 → 완료)

[두 개의 records] ★★
app.py의 records 와 script.js의 records 는 이름만 같고 완전 남남
    서버 records = 원본 (source of truth)
    JS   records = 사본 (화면 그리려고 받아둔 것)
서로 직접 못 봄. 요청-응답으로만 대화

[데이터 흐름 원칙] (b)방식
    (a) 브라우저에도 push + 서버에도 전송 → 두 곳 각자 관리 → 어긋남 위험
    (b) 서버에만 보내고 → 전체 다시 받아오기 → 항상 서버가 정답  ★채택
저장 실패했는데 화면엔 추가된 것처럼 보이는 사고 방지

    POST → loadRecords() → records 통째 교체 → 렌더
    ※ 그래서 records.push() 는 불필요 (어차피 덮어씌워짐)

앞서 배운 단방향 데이터 흐름의 확장:
    상태 바뀜 → 화면 전체 다시 그림
    서버 바뀜 → 데이터 전체 다시 받음

[메모리 vs 디스크] ★
app.py의 records = 메모리(RAM)에만 존재
→ 서버 재시작하면 전부 소멸 (파이썬 변수가 프로그램 끝나면 사라지는 것과 같음)
→ 살아남게 하려면 디스크에 써야 함 (파일 or DB)  ← 다음 단계
